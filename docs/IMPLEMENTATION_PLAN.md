# 📋 IMPLEMENTATION PLAN — Hermes Agent + Ngrok Automation

## Executive Summary

This document outlines the architecture, security model, and deployment strategy for **Hermes Agent** (NousResearch) running on an Ubuntu Minimal Server with **ngrok** tunneling, following the exact pattern of the proven **n8n-ngrok-automation** project.

**Key Differentiator from n8n:**
- n8n injects the public ngrok URL back into its config (`WEBHOOK_URL`)
- Hermes Agent doesn't require self-registration — the dashboard just needs to be reachable
- Our URL watcher **tracks and logs** changes without needing container restarts

## 2. Security Model

### 2.1 Layers of Protection

```
Public Internet
    ↓
    ↓ HTTPS/TLS encryption (ngrok provides)
    ↓
 ngrok Basic Auth Challenge
    ├─ Username: hermes (auto-generated, same for all)
    ├─ Password: 24-char hex (auto-generated at deploy time, stored in credentials.txt)
    └─ Browser prompts for username/password
    ↓
 Hermes Dashboard (running in INSECURE mode internally)
    ├─ HERMES_DASHBOARD_INSECURE=1 is SAFE here
    │   because the ngrok basic-auth is the external gate
    ├─ The dashboard itself doesn't need to know about TLS
    │   (ngrok terminates the HTTPS)
    └─ (Optional later) Add Hermes' own OAuth inside the dashboard
        for an additional internal auth layer
```

### 2.2 Why This is Secure

1. **External Gate (ngrok Basic Auth)**
   - Requires username + password to even reach Hermes
   - 24-char hex password = 96 bits of entropy
   - Credentials stored locally in `credentials.txt` (chmod 600)
   - Cannot be guessed via brute-force (ngrok rate-limits)

2. **Transport Security**
   - All traffic from internet → ngrok is HTTPS encrypted
   - ngrok → localhost (Docker) is over private Docker network
   - No exposure of internal IPs/ports

3. **Data Privacy**
   - Hermes data stored in `~/.hermes/` (local only)
   - `.env` file with API keys is chmod 600
   - Never committed to Git (see `.gitignore`)

4. **Future Hardening**
   - Can add Hermes' built-in OAuth after setup
   - Can add reverse-proxy (Nginx) between ngrok and Hermes
   - Can restrict Ngrok IP allowlist (paid plan feature)

### 2.3 Threat Model

| Threat | Mitigation |
|--------|------------|
| **Brute-force login** | ngrok rate-limits + 24-char password |
| **Network sniffing** | HTTPS/TLS encryption (ngrok) |
| **URL enumeration** | Free ngrok = random URL, impossible to guess |
| **Data breach** | All data local, never centralized |
| **Container escape** | Linux namespaces + seccomp (Docker defaults) |
| **Port scanning** | VM behind NAT, only egress (ngrok) visible |

## 3. Configuration Strategy

### 3.1 Environment Variables

**Generated at deploy time** (`hermes-ngrok-deploy.sh`):

```bash
# Required
NGROK_AUTHTOKEN      # User provides their ngrok token
NGROK_AUTH_USER      # Fixed: "hermes"
NGROK_AUTH_PASS      # Auto-generated: 24-char hex
API_SERVER_KEY       # Auto-generated: 48-char hex (for API auth)

# Optional (configure later via web portal OR edit .env)
OPENROUTER_API_KEY   # For OpenRouter LLM provider
GOOGLE_API_KEY       # For Google Gemini LLM provider
ANTHROPIC_API_KEY    # For Anthropic Claude (optional)
OPENAI_API_KEY       # For OpenAI (optional)
```

**File:** `~/hermes-ngrok/.env` (chmod 600, not in Git)

### 3.2 LLM Provider Configuration

**Recommended Flow:**

1. **Immediate (Day 1):**
   - Deploy Hermes
   - Access web dashboard
   - Test basic functionality (no LLM yet)

2. **Later (Day 2+):**
   - Get free API keys:
     - **OpenRouter:** https://openrouter.ai/keys (free tier, supports multiple models)
     - **Gemini:** https://aistudio.google.com/app/apikey (free tier)
   - Add keys via **web portal** (simplest), OR
   - Add keys to `~/.hermes-ngrok/.env`, then `bash scripts/restart.sh`

**Why not require keys at deploy time?**
- Users may not have API keys ready
- Keys can be generated after seeing the dashboard
- Reduces friction for initial setup

## 4. Deployment Steps (Automated)

The `hermes-ngrok-deploy.sh` script automates all 10 steps:

### Step 1: Prerequisites Check
- Detects OS (Ubuntu 20.04 LTS+)
- Checks for Docker, Python3, curl, jq, netcat, openssl
- Flags missing dependencies

### Step 2: Docker Installation
- Installs Docker Engine + Compose v2 (if needed)
- Adds user to `docker` group
- Starts Docker daemon
- (Optional) Prompts to run `newgrp docker`

### Step 3: Configuration Collection
- **Prompts for:**
  - ngrok Auth Token (required)
  - Re-uses existing token if `.env` found
- **Auto-generates:**
  - Dashboard password (24-char hex)
  - API server key (48-char hex)
  - Stores in `credentials.txt` (chmod 600)

### Step 4: Directory Structure
- Creates:
  - `~/hermes-ngrok/` (project root)
  - `~/hermes-ngrok/scripts/` (helper scripts)
  - `~/hermes-ngrok/logs/` (log files)
  - `~/.hermes/` (persistent Hermes data, chmod 700)

### Step 5: Generate Config Files
- **`.env`** — environment variables (chmod 600)
- **`docker-compose.yml`** — two-container setup (Hermes + ngrok)
- **`.gitignore`** — prevents accidental secret commits

### Step 6: Generate Helper Scripts
- `start.sh` — start all containers
- `stop.sh` — stop all containers
- `restart.sh` — restart (data preserved)
- `status.sh` — show container status + URL
- `get-url.sh` — print current ngrok public URL
- All scripts in `~/hermes-ngrok/scripts/`

### Step 7: Generate URL Watcher
- **`url-watcher.sh`** — polls ngrok API every 30 seconds
  - Detects URL changes
  - Logs with ISO8601 timestamps
  - Updates `current-url.txt`
  - (Optional) sends Telegram notifications

### Step 8: Register systemd Service
- Creates `/etc/systemd/system/hermes-url-watcher.service`
- **Auto-starts on VM boot**
- Restarts on failure
- Logs to systemd journal (viewable with `journalctl`)

### Step 9: Pull Docker Images
- Pulls `nousresearch/hermes-agent:latest`
- Pulls `ngrok/ngrok:latest`
- (Can take 2-5 minutes depending on internet)

### Step 10: Start Services + Display Info
- Runs `docker compose up -d`
- Waits for ports to respond (with timeouts)
- Starts URL watcher service
- Displays:
  - Public ngrok URL
  - Dashboard credentials
  - Quick commands
  - Next steps

## 5. URL Watcher Logic

### 5.1 Why URL Watcher Exists

**Problem:** Free ngrok plan generates a new random URL on each container restart.

**Solution:** Poll ngrok Management API (`http://localhost:4040/api/tunnels`) every 30 seconds.

**n8n vs. Hermes:**
- **n8n:** Needs URL injected as `WEBHOOK_URL` → requires container restart
- **Hermes:** Doesn't require self-registration → only needs to be reachable
- **Ours:** Just track & log the URL, user checks it when needed

### 5.2 Watcher Flow

```
Start URL Watcher
    ↓
Wait for ngrok management API (max 120s)
    ↓
Enter polling loop (every 30s):
    ├─ GET http://localhost:4040/api/tunnels
    ├─ Parse JSON: tunnels[0].public_url
    ├─ Compare with last known URL
    │
    ├─ IF URL changed:
    │   ├─ Log: "URL CHANGED → old → new"
    │   ├─ Write new URL to current-url.txt
    │   ├─ (Optional) Send Telegram notification
    │   └─ Print banner to console
    │
    └─ Sleep 30s, loop

Log file: ~/hermes-ngrok/logs/url-watcher.log
Example:
  [2026-06-02 14:50:15] INFO: URL Watcher started
  [2026-06-02 14:50:18] INFO: ngrok API is up
  [2026-06-02 14:50:22] INFO: URL ACQUIRED → https://abc123.ngrok-free.dev
  [2026-06-02 15:20:45] INFO: URL CHANGED → abc123 → xyz789
```

### 5.3 How to Check Current URL

```bash
# Option 1: Run get-url.sh
bash ~/hermes-ngrok/scripts/get-url.sh

# Option 2: Read the file
cat ~/hermes-ngrok/current-url.txt

# Option 3: View watcher logs
tail -f ~/hermes-ngrok/logs/url-watcher.log

# Option 4: Check systemd service
sudo systemctl status hermes-url-watcher
```

## 7. Co-Deployment Considerations

### 7.1 Running Both n8n and Hermes (Same VM)

Both services can run on the same Ubuntu VM:

**Resources:**
- n8n: ~300MB RAM (idle), uses port 5678
- Hermes: ~400MB RAM (idle), uses ports 9119 + 8642
- Docker overhead: ~100MB
- **Total:** ~1GB RAM baseline (scales with workload)

**Network (ngrok):**
- n8n tunnel: Exposes port 5678 (n8n UI) to internet
- Hermes tunnel: Exposes port 9119 (Hermes dashboard) to internet
- **Same ngrok account:** Can have multiple tunnels (free tier limits = 1 tunnel, but paid allows more)
- **Solution:** If both needed simultaneously, upgrade ngrok plan OR use separate ngrok accounts

**Data:**
- n8n: `/opt/n8n/n8n_data/`
- Hermes: `~/.hermes/`
- **No conflicts** (different paths, different volumes)

**Recommendation:**
- ✅ Same VM for **sequential** use (deploy one, then the other)
- ⚠️ Paid ngrok for **simultaneous** tunnels
- Or use **separate VMs** if both needed at once

## 8. Monitoring & Maintenance

### 8.1 Health Checks

**Built-in Docker health checks:**
```yaml
# Hermes dashboard
test: ["CMD", "curl", "-f", "http://localhost:9119/health"]
interval: 30s, retries: 5

# ngrok management API
test: ["CMD", "curl", "-f", "http://localhost:4040/api/tunnels"]
interval: 30s, retries: 3
```

**Manual checks:**
```bash
# Container status
docker compose ps

# Service status
sudo systemctl status hermes-url-watcher

# Logs
docker logs hermes-agent
docker logs hermes-ngrok
sudo journalctl -u hermes-url-watcher -f
```

### 8.2 Maintenance Tasks

| Task | Frequency | Command |
|------|-----------|----------|
| Check URL is current | Daily | `bash scripts/get-url.sh` |
| View logs | As needed | `docker compose logs -f` |
| Update Hermes image | Monthly | `bash scripts/update.sh` |
| Backup Hermes data | Monthly | `tar czf hermes-backup-$(date +%s).tar.gz ~/.hermes/` |
| Restart all services | If issues | `bash scripts/restart.sh` |

### 8.3 Troubleshooting

**Problem:** Containers won't start
```bash
# Check Docker daemon
sudo systemctl status docker

# Check logs
docker compose logs

# Verify .env file exists
cat ~/hermes-ngrok/.env
```

**Problem:** ngrok URL not updating
```bash
# Check ngrok management API
curl -s http://localhost:4040/api/tunnels | jq

# Check watcher service
sudo systemctl status hermes-url-watcher
sudo journalctl -u hermes-url-watcher -n 50
```

**Problem:** Can't access dashboard
```bash
# Get current URL
bash scripts/get-url.sh

# Check credentials
cat credentials.txt

# Verify ngrok tunnel is up
docker logs hermes-ngrok | tail -20
```

## 9. Disaster Recovery

### 9.1 Data Persistence

**Hermes data is persistent across:**
- ✅ Container restarts
- ✅ docker compose down/up
- ✅ Hermes image updates
- ✅ VM reboots (via systemd)
- ❌ Deletion of `~/.hermes/` directory

**To backup:**
```bash
tar czf ~/hermes-backup-$(date +%Y%m%d-%H%M%S).tar.gz ~/.hermes/
```

**To restore:**
```bash
cd ~ && tar xzf hermes-backup-20260602-150000.tar.gz
# Then restart: bash scripts/restart.sh
```

### 9.2 Uninstall

**Preserve data, remove containers:**
```bash
./hermes-ngrok-deploy.sh --uninstall
```

This will:
- ✅ Stop and remove all containers
- ✅ Stop and unregister systemd service
- ✅ Remove project directory (`~/hermes-ngrok/`)
- ✅ **PRESERVE** `~/.hermes/` (all your data)
